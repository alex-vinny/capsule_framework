    @capsule/core¶

    @capsule/core — the JavaScript API an app uses to reach the native shell.

    Each native API is a ready-made singleton (camera, db, push, …). Inside the Capsule shell calls go over the native bridge; in a plain browser a web fallback answers instead, so an app can be developed without a device. Server routes for the on-device /api bundle live in the @capsule/core/routes entry point.

    AlertStyle¶

    Per-dialog visual style.

    IMPORTANT — this is NOT a CSS layer. Every property maps to a specific, tested native API call. Properties not listed here are not supported on any platform; they are intentionally absent (not forgotten). Unsupported things include: per-button colors, custom fonts, layout/padding, entry/exit animations, and dialog width.

    Colors: hex string — #RGB, #RRGGBB, or #AARRGGBB (alpha-first). Sizes: sp on Android (scale-independent pixels), pt on iOS. Lengths: dp on Android, pt on iOS.

    Each property documents its exact platform behaviour below. Properties marked "iOS: not supported" are silently ignored on iOS — they do not throw, but they have no visual effect.

    Properties¶

    Property Type Description
    accentColor? string Button text color — applied to all button slots. Per-button colors are not supported by either platform's native dialog API. Android: getButton(slot).setTextColor() — fully supported. iOS: UIAlertController.view.tintColor — fully supported.
    backgroundColor? string Dialog panel background color. Android: GradientDrawable on dialog.window — fully supported. iOS: NOT SUPPORTED — UIAlertController background is system-controlled and cannot be changed via public API. Setting this has no effect on iOS.
    buttonAllCaps? boolean Whether button labels are rendered in uppercase. Android: Button.isAllCaps — fully supported. Platform default is true. iOS: NOT SUPPORTED — iOS buttons are always mixed-case. This property is silently ignored on iOS.
    cornerRadius? number Dialog panel corner radius in dp (Android) / pt (iOS). Android: GradientDrawable.cornerRadius on dialog.window — fully supported. iOS: NOT SUPPORTED — UIAlertController corner radius is system-controlled and overridden by internal masking. Setting this has no effect on iOS.
    dimAmount? number Backdrop scrim opacity behind the dialog. Range: 0.0 (fully transparent) → 1.0 (fully opaque black). Values outside this range are clamped. Platform default is ~0.5. Android: Window.setDimAmount() — fully supported. iOS: NOT SUPPORTED — UIAlertController scrim is system-controlled. Setting this has no effect on iOS.
    messageColor? string Message body text color. Android: TextView(android.R.id.message).setTextColor() — fully supported. iOS: NSAttributedString on alertController.setValue — fully supported.
    messageSize? number Message body text size in sp (Android) / pt (iOS). Android: TextView.setTextSize(COMPLEX_UNIT_SP, value) — fully supported. iOS: NSAttributedString font attribute — fully supported.
    titleColor? string Title text color. Android: TextView(android.R.id.title).setTextColor() — fully supported. iOS: NSAttributedString on alertController.setValue — fully supported.
    titleSize? number Title text size in sp (Android) / pt (iOS). Android: TextView.setTextSize(COMPLEX_UNIT_SP, value) — fully supported. iOS: NSAttributedString font attribute — fully supported.

    AppModule¶

    App lifecycle + deep links. Infrastructure, not just an API: push tap-routing and OTA foreground re-checks both build on the events emitted here.

    • onStateChange / onResume / onPause — foreground & background transitions. On Android these come from ProcessLifecycleOwner, so internal activity transitions (e.g. opening the camera picker) do not spuriously fire background/foreground.
    • onUrlOpen — a deep link arriving while the app is already running.
    • getLaunchUrl — the deep link the app was cold-started with (consumed once; resolves null afterwards or on a normal launch).

    Methods¶

    getLaunchUrl()¶
    getLaunchUrl(): Promise<{
  url: string | null;
}>;

    The URL the app was cold-started with via a deep link, or null for a normal launch. Consume-once: a second call resolves null.

    Cold-start links surface here and not through onUrlOpen (which fires only for links arriving while the app is already running) — so route on both at startup to cover every entry path:

    const { url } = await app.getLaunchUrl()
if (url) route(url)            // launched by a deep link
app.onUrlOpen(({ url }) => route(url))  // links while running

    AppState¶

    Foreground/background state of the app.

    Deliberately a binary contract: Android (resumed/paused/stopped) and iOS (active/inactive/background) disagree on the middle states, but both agree on "is the app in the foreground and interactive?". Modelling that single bit keeps the cross-platform seam honest — the same listener fires identically on both platforms. A richer state enum can be layered on later without breaking this shape.

    Properties¶

    Property Type Description
    isActive boolean true while the app is foregrounded and receiving input.

    Bridge¶

    Contract that all modules depend on. Allows injection of FakeBridge in tests.

    Messages are JSON-RPC 2.0 over the WebView: requests carry an id and get exactly one response; notifications carry no id and fan out to every on() subscriber.

    CapabilitiesModule¶

    Reports which native capabilities — and at what version — the installed shell provides. This is the OTA-gating contract (Phase 6): a Server Code Push bundle can refuse to call a native API the user's shell predates, rather than failing at runtime with METHOD_NOT_FOUND. Each native module declares its own version; the shell answers the aggregate here.

    DbModule¶

    Methods¶

    schema()¶
    schema(version, migrate): void;

    Registers migration version (an integer ≥ 1) for tables you manage with db.sql. Pending migrations run in version order, each in its own transaction, before the next database operation; the applied version is kept in SQLite's PRAGMA user_version. Add a new version for each change — never edit one that has shipped.

    If the database is already at a version newer than any registered (e.g. after an OTA rollback to an older bundle), every operation fails with SCHEMA_VERSION_REGRESSION.

    transaction()¶
    transaction<T>(fn): Promise<T>;

    Runs fn in a transaction: committed when it resolves, rolled back when it throws (the error is rethrown). Resolves to fn's result.

    The database runs one thing at a time: while a transaction is open, other db.sql and db.transaction calls wait for it. So inside fn use tx.sql — awaiting db.sql or a nested db.transaction there would wait for the transaction it is part of, forever.

    PushModule¶

    Remote push notifications (FCM / APNs).

    Tap routing mirrors app deep links (the same cold/warm split #3 proved on device): a tap on a notification that cold-launches the app surfaces through the consume-once getLaunchNotification; a tap while the app is already running/backgrounded fires onNotificationTap. Route on both at startup to cover every entry path, just like app.getLaunchUrl + app.onUrlOpen:

    const { message } = await push.getLaunchNotification()
if (message) route(message)               // launched by a notification tap
push.onNotificationTap((msg) => route(msg)) // taps while running
push.onMessage((msg) => toast(msg))         // foreground arrivals

    Channel methods are Android-only (API 26+) and silently no-op on iOS.

    FilesystemDirectory¶

    type FilesystemDirectory = "data" | "cache" | "documents";

    Logical storage location. Apps address files by (directory, relative path) rather than absolute paths, so the same code resolves correctly on Android, iOS, and the browser fallback.

    All three map to app-private storage that is deliberately kept outside the OTA-swappable bundle dirs (www/ + server/bundle.js) — a code-push bundle swap never touches user data written here.

    • data — persistent app data. Survives until explicitly deleted.
    • cache — same API, but the OS may reclaim it under storage pressure.
    • documents — persistent, user-facing documents (export targets).
